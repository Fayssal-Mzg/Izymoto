# Rapport — lot 1.1 « empreinte différée » (SENSIBLE)

Date : 2026-10-13 · Branche : `lot/1.1-empreinte-differee` (depuis `lot/0.5-regles`) · Plan : `docs/plans/2026-10-13-paiement-empreinte-et-connect.md` · Décision : D-013.

## Résultat
- Course à ≥ 5 jours : carte enregistrée (SetupIntent off_session, 3-D Secure) → réservation `card_saved` ; tâche quotidienne Vercel Cron (`/api/cron/deferred-holds`, 05:00 UTC, `CRON_SECRET`) qui pose l'empreinte à J-3.
- Refus / authentification : `action_required`, e-mail client (page `/paiement/confirmer/[bookingId]`), alerte admin, badge « Paiement à confirmer », nouvelle tentative chaque matin ; arrêt (« failed ») un jour après le départ ou si la course n'est plus active, avec annulation du paiement ouvert et alerte admin.
- Robustesse : PaymentIntent créé sans confirmation puis id enregistré avant confirmation (pas de double empreinte), verrou transactionnel, écriture finale en transaction (course annulée → empreinte libérée), webhook aligné.
- Hybride refusé au-delà de 5 jours ; règle Firestore : `deferred_*` créés par le serveur seulement.
- Courses à moins de 5 jours : flux inchangé.
